# Phase 3 — Design system and components

**Gate: the `browser` Vitest project is green and the app is fully usable.**

Build bottom-up: `dice-face` → `add-player-form` / `theme-toggle` / `language-switcher` →
`score-cell` → `score-table` → `score-picker` → `score-dialog` → `scoreboard`.

---

## Design tokens

`shadcn init` with base colour **neutral** wrote the OKLCH token set into `src/index.css`.
Use those tokens everywhere: `bg-background`, `text-foreground`, `text-muted-foreground`,
`border-border`, `bg-card`, `bg-accent`, `bg-primary`, `bg-destructive`, `ring-ring`.

**Do not reintroduce the old `--bg` / `--card` / `--table-border` / `--accent` custom
properties.** They are replaced wholesale. The old palette's indigo/cyan character is
deliberately dropped in favour of the stock neutral theme.

The generated stylesheet already declares a class-driven `@custom-variant dark`, so the
pre-paint script's `.dark` on `<html>` works out of the box. The hand-written
`@custom-variant` the Svelte app needed is gone.

One addition beyond the shadcn defaults:

```css
/* The dice read as physical objects and look identical in both themes, exactly
   as they did before. Deliberately NOT theme tokens. */
:root {
	--dice-bg: #ffffff;
	--dice-stroke: #374151;
	--dice-dot: #374151;
}
```

Scores are compared column to column, so **every number in the table gets Tailwind's built-in
`tabular-nums`**. No custom class needed.

Dark is the default theme. Both themes must look finished.

## Layout

- Page shell: `min-h-dvh bg-background` wrapping
  `mx-auto w-full max-w-6xl px-4 py-6 sm:px-6 sm:py-10`.
- Header: title and subtitle on the left; language `Select`, theme toggle and Reset on the
  right. `flex-col` below `sm`, `sm:flex-row sm:items-center sm:justify-between`, `gap-4`.
- **Empty state** (no players): a single `Card` — the "Add Players" heading and the form.
  **No table renders at all.** This is asserted by a test.
- **Active state**: a players `Card` (chips plus the "Add More Players" form), then the score
  table.

There is exactly one breakpoint in play (`sm`). Do not invent a responsive system.

## The score table

This is where the design work pays off. Use the shadcn `Table` primitives, wrapped in
`<div className="relative overflow-x-auto rounded-lg border">`.

- **Sticky category column.** `sticky left-0 z-20 bg-card` on the first cell of every row.
  With four or five players on a phone this is the difference between usable and unusable —
  it is the single highest-value improvement in the rewrite.
- **Sticky header row** (`sticky top-0 z-10`) so player names stay visible while scrolling a
  15-row card. The corner cell needs both, at the higher z-index.
- All numeric cells: `tabular-nums text-center`.
- Score cells stay full-cell `<button>`s with `min-h-12 w-full`. The 48 px touch target is
  deliberate — keep it.
- Total rows: `bg-muted/40 font-semibold`. Grand Total: `text-lg font-bold`.

### Row order — fixed, do not change

1. Six upper categories (ones → sixes)
2. **Upper Total**
3. **Bonus** — note Upper Total comes _before_ Bonus
4. Nine lower categories (pair, two-pairs, three-of-a-kind, four-of-a-kind, full-house,
   small-straight, large-straight, yahtzee, chance)
5. **Lower Total**
6. **Grand Total**

Section boundaries: `border-b-2 border-primary/40` under the Bonus row and
`border-t-2 border-primary/40` above Grand Total, replacing the old inline accent styles.

### The Bonus row

Label is `t.scoreboard.bonus(UPPER_BONUS_THRESHOLD)` → "Bonus (63+ pts)". An earned bonus
renders `<Badge variant="secondary">35</Badge>`; an unearned one renders `0` in
`text-muted-foreground`.

The old green is dropped — the neutral palette has no success token, and a badge reads as
"achieved" without inventing one.

### Score cells

```tsx
<button
	className="min-h-12 w-full px-4 py-3 transition-colors hover:bg-accent"
	aria-label={t.scoreboard.scoreFor(t.categories[category], player.name)}
	onClick={() => onOpen(category, player.id)}
>
	{score !== null ? <span className="tabular-nums font-medium">{score}</span> : /* empty */}
</button>
```

**The check is `!== null`, never truthiness.** A cell holding `0` renders `0` and is a scored
cell in every respect.

**Empty cells** show a muted `–` at rest and reveal the localized `t.scoreboard.clickToScore`
affordance on hover and `focus-visible`. With four players that is 60 cells; repeating the
full string in every one is visual noise. The `aria-label` is unchanged, so screen-reader
behaviour is identical to today.

## `dice-face.tsx`

Port the SVG geometry **exactly** — the sizes and pip positions are tuned.

```tsx
<svg width={size} height={size} viewBox={`0 0 ${size} ${size}`} aria-hidden="true">
	<rect
		x={0.5}
		y={0.5}
		width={size - 1}
		height={size - 1}
		rx={size * 0.12}
		fill="var(--dice-bg)"
		stroke="var(--dice-stroke)"
		strokeWidth="1"
	/>
	{dots.map(([dx, dy]) => (
		<circle
			key={`${dx},${dy}`}
			cx={size / 2 + dx * size * 0.2}
			cy={size / 2 + dy * size * 0.2}
			r={Math.max(3, Math.round(size * 0.08))}
			fill="var(--dice-dot)"
		/>
	))}
</svg>
```

Dot layouts, each `[dx, dy]` in `{-1, 0, 1}`:

| Face | Dots                                         |
| ---- | -------------------------------------------- |
| 1    | `[[0,0]]`                                    |
| 2    | `[[-1,-1],[1,1]]`                            |
| 3    | `[[-1,-1],[0,0],[1,1]]`                      |
| 4    | `[[-1,-1],[-1,1],[1,-1],[1,1]]`              |
| 5    | face 4's dots + `[0,0]`                      |
| 6    | `[[-1,-1],[-1,0],[-1,1],[1,-1],[1,0],[1,1]]` |

An out-of-range value renders **zero pips and must not throw**. Default `size = 40`. Sizes
used in the dialog: **20** (two-column pickers), **24** (upper / pair / 3- and 4-of-a-kind /
straights), **28** (chance chips), **32** (chance grid). The SVG is always `aria-hidden`.

JSX translation from the Svelte original: `stroke-width` → `strokeWidth`, `class` →
`className`. `viewBox`, `rx` and `aria-hidden` are already correct.

## `add-player-form.tsx`

A real `<form>` so Enter submits natively.

```tsx
function submit(event: React.FormEvent) {
	event.preventDefault();
	if (!name.trim()) return;
	onAdd(name.trim());
	setName('');
}
```

The `Input` carries both `placeholder` and a matching `aria-label`, both
`t.addPlayerForm.playerNamePlaceholder`. The submit `Button` is `disabled` while the trimmed
name is empty. The input clears on successful submit and at no other time.

Drop the `label` prop from the old component — no caller ever passed it.

This form renders in **both** states: alone in the empty-state card, and again under "Add
More Players" in the players card.

## `score-dialog.tsx`

shadcn `Dialog` supplies the whole accessibility contract the native `<dialog>` gave for free
— focus trap, focus restore on close, Escape, `aria-labelledby` via `DialogTitle`, inert
background, backdrop click — plus a portal, scroll lock and animation the old one lacked.

It also **fixes a real gap**: today Escape restores focus (the browser closes the dialog), but
clicking Cancel or submitting a score does not, because Svelte just removes the element and
focus falls to `<body>`. shadcn's Dialog restores focus on every close path.

```tsx
<Dialog open={selected !== null} onOpenChange={(open) => !open && setSelected(null)}>
	<DialogContent className="max-h-[85dvh] max-w-2xl overflow-y-auto">
		{selected && (
			<ScorePicker
				key={`${selected.playerId}:${selected.category}`}
				category={selected.category}
				current={selectedPlayer?.scores[selected.category] ?? null}
				onScore={(score) => {
					/* store + close */
				}}
				onErase={() => {
					/* store + close */
				}}
				onClose={() => setSelected(null)}
			/>
		)}
	</DialogContent>
</Dialog>
```

**The `key` is load-bearing.** The picker's local state (`firstPair`, `secondPair`,
`threeOfAKind`, `fullHousePair`, `selectedDice`) currently resets because the whole
`<dialog>` unmounts. Keying on player + category reproduces that exactly.

The trap: the shadcn idiom is an always-mounted `<Dialog open={...}>`. Ported that way,
`useState` survives across opens and a half-picked two-pairs selection leaks into the next
category the user opens. **Conditional mount is the braces; the `key` is the belt.** Keep
both.

`DialogTitle` renders `t.scoreModal.scoreFor(t.categories[category])`. Put the per-category
hint text (currently a bare `<p>`) into `DialogDescription`, so the dialog is described as
well as labelled.

Footer: `Erase score` and `Cancel`, side by side, each `flex-1`. **`Erase score` renders only
when `current !== null`** — so it _does_ appear for a category scratched to `0`. That case has
a test named after it.

## `score-picker.tsx` — the nine category panels

Every submit path goes through one guard, mirroring the store's own:

```ts
onScore(Number.isNaN(score) ? 0 : score);
```

Keep both guards. The store's is what `game-store.test.ts` asserts; this one is what the
picker tests assert.

| Category        | Input                                                                                                             | Score                    | "None"                           |
| --------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------ | -------------------------------- |
| ones…sixes      | 6 rows for counts 0–5, each showing `count` dice at size 24                                                       | `count × faceValue`      | the count-0 row, labelled "None" |
| pair            | 7 rows over `[0,1,2,3,4,5,6]`; the 0 row renders "None"                                                           | `value × 2`              | value 0 → 0                      |
| two-pairs       | A separate "None" row, then a 2-column grid ("First Pair" / "Second Pair"), 6 options each, dice at size 20       | `first × 2 + second × 2` | dedicated row → 0                |
| three-of-a-kind | "None" row + 6 rows, three dice at size 24                                                                        | **`value × 3 + 3`**      | dedicated row → **0**, not 3     |
| four-of-a-kind  | "None" row + 6 rows, four dice at size 24                                                                         | **`value × 4 + 1`**      | dedicated row → **0**, not 1     |
| full-house      | "None" row + 2-column grid: triple (three dice size 20, label `{v}×3`) and pair (two dice size 20, label `{v}×2`) | `three × 3 + pair × 2`   | dedicated row → 0                |
| small-straight  | "None" row + one row showing faces `[1,2,3,4,5]` at size 24                                                       | flat `30`                | → 0                              |
| large-straight  | "None" row + one row showing faces `[2,3,4,5,6]` at size 24                                                       | flat `40`                | → 0                              |
| yahtzee         | "None" row + one row                                                                                              | flat `50`                | → 0                              |
| chance          | "None" row (also clears the buffer) + a 3-column grid of 6 die buttons at size 32                                 | `sum(selected)`          | → 0                              |

All scoring goes through the exported functions in `src/lib/scoring.ts`. Do not inline the
arithmetic anywhere.

### Mechanics that are easy to get wrong

- **Two-pairs and full-house auto-submit the moment both halves are non-null.** There is no
  confirm button. Re-picking either column immediately re-submits with the new combination.
- **`twoPairsScore` does not require distinct pairs.** `twoPairsScore(1, 1) === 4` is an
  explicit test, and the UI allows the same value in both columns.
- **Chance auto-submits at exactly 5 dice.** Die buttons are `disabled` once 5 are selected.
  Once at least one die is picked, a panel appears with: a "Clear All" button, the selected
  dice as chips (each with its own remove button, `aria-label` = `t.scoreModal.removeDie(v)`),
  a running-total box, and `t.scoreModal.moreDiceToSelect(5 - selected.length)`.
- **Straights do no dice validation.** The faces shown are decorative; the score is flat.
- **"None" always scores a literal `0`,** never the house-rule remainder. This matters because
  `threeOfAKindScore(0)` is `3` and `fourOfAKindScore(0)` is `1` — calling the scoring function
  with 0 would be wrong. Call `onScore(0)` directly.
- Die-add buttons carry `aria-label={t.scoreModal.addDie(value)}`.

Use `ToggleGroup type="single"` for the two-column pickers — it gives correct pressed
semantics without hand-rolling `aria-pressed`.

## Confirmation dialogs

The one deliberate behaviour change. Use shadcn `AlertDialog`.

| Action        | Title                   | Body                                                                | Confirm                            |
| ------------- | ----------------------- | ------------------------------------------------------------------- | ---------------------------------- |
| Reset         | "Reset the scoreboard?" | "This removes all players and their scores. This cannot be undone." | "Reset" (`variant="destructive"`)  |
| Remove player | "Remove {name}?"        | "Their column and all their scores will be deleted."                | "Remove" (`variant="destructive"`) |

New translation keys in **both** locales:
`scoreboard.confirmReset{Title,Body,Confirm}`,
`scoreboard.confirmRemove{Title,Body,Confirm}` (Title takes `name`), and a shared
`common.cancel`.

German: "Punktetafel zurücksetzen?" / "Dadurch werden alle Spieler und ihre Punkte entfernt.
Das kann nicht rückgängig gemacht werden." / "Zurücksetzen"; "{name} entfernen?" / "Die Spalte
und alle Punkte werden gelöscht." / "Entfernen"; "Abbrechen".

Extract a small `confirm-dialog.tsx` wrapper so both call sites share one implementation.

**Everything else stays instant and unconfirmed** — scoring, erasing a category, adding a
player, switching theme or language.

## Accessibility contract

Every item here is currently pinned by a test or an explicit fix. Preserve all of it.

- Every score cell has `aria-label={t.scoreboard.scoreFor(category, player)}`. There are
  exactly **15 per player**, and all are keyboard reachable — they are `<button>`s inside
  `<td>`s, not clickable `<td>`s.
- Remove-player buttons: `aria-label={t.scoreboard.removePlayer(name)}`.
- Remove-die: `t.scoreModal.removeDie(value)`. Add-die: `t.scoreModal.addDie(value)`.
- Theme toggle: `aria-pressed` reflecting `isDark`, plus an `aria-label`.
- Language select: `aria-label={t.language.switchLabel}`.
- Add-player input: `placeholder` and a matching `aria-label`.
- All `DiceFace` SVGs: `aria-hidden="true"`.
- `<html lang>` stays honest — set pre-paint and on every locale change.
- The dialog is labelled by its title and described by its hint.
- Visible focus rings everywhere. shadcn's `ring-ring` handles this; do not remove focus
  outlines.
